# Architecture Decision Records

This directory holds the OCP Architecture Decision Records (ADRs) — short documents that capture the **why** behind structural choices.

Read these before proposing governance, SPOT (single-source-of-truth), or process changes.

## Numbering

ADRs start at `0002`. The first one (`0001`) was reserved for an early
internal proposal that was superseded before publication; `0002` is
deliberately the first published record so the archived `0001` slot
remains a placeholder rather than being silently renumbered.

New ADRs increment from the highest existing number. Filenames are
`NNNN-<short-slug>.md`.

Records what is deliberately NOT folded — `oneOffRequests` (a `-p` **spawn** counter, not a request counter), `queued`/`queueRejections` (lane-specific gauges already mirrored under `concurrency.*`), and the per-model `0` elapsed sentinel. Issue #361, following PR #389's auth half. |
| [0019](0019-inbound-origin-gate.md) | Reject State-Changing Requests Carrying a Foreign `Origin` | Why a request whose `Origin` is outside the loopback/private-range allowlist is refused `403` on any method but `GET`/`HEAD`. There was **no CSRF defense and none had been considered** (`git grep -niE 'csrf|cross-site request'` → zero, positive control `Allow-Origin` → two files). The chain was **measured against a live default instance**, not reasoned about: no inbound `Content-Type` check (so a CORS-safelisted `text/plain` POST needs no preflight), localhost admitted unconditionally, `ALLOWED_TOOLS` defaulting to a set containing `Bash`/`Write`/`Edit`, and the spawned `claude` executing them **without prompting** — proven with a locally-written nonce returned through the proxy. So the exposure was a visited web page running commands as the operator, blind, on the **default loopback deployment** rather than in the frozen LAN mode. An absent `Origin` changes nothing, which is what makes the gate cost no client a change. Records why a `Content-Type` requirement was designed and **not** taken, with its measured cost. Class **Hybrid**; B.2 half is ADR 0006 route (b). |
| [0020](0020-declared-hosts.md) | `OCP_ALLOWED_HOSTS`: Which Host Names May Vouch for a Same-Origin Request | Closes the one boundary ADR 0019 left open (#446) and the mirror finding that arrived with it — **`Host` was being pulled in opposite directions**. DNS rebinding makes a request *genuinely* same-origin, so no `Origin` check can refuse it; a reverse proxy that rewrites `Host` makes a legitimate dashboard *never* same-origin, so the arm can never admit it. The discriminator is **not "is this local"** but **"could an attacker with public DNS point this name at 127.0.0.1?"** — an IP literal involves no lookup and RFC 6761/6762 reserved names have no public record, so both stay config-free; every other name must be declared. A declared origin is admitted outright (rescuing the rewriting proxy) and echoed into `Access-Control-Allow-Origin`, or the browser would discard a response the server allowed. Breaking for exactly one shape: a public DNS name resolving straight to the box — the same shape rebinding imitates. Class **Hybrid**; ADR 0006 route (b). |

## When to write a new ADR

Open one whenever:

- A structural rule is being added or changed (e.g., new SPOT, new boundary, new CI guardrail).
- A decision encodes a lesson from an incident or drift.
- A future contributor reading the code alone could plausibly undo or re-litigate the choice.

Skip ADRs for routine implementation choices (algorithm pick, naming) — those belong in commit messages.

## Format

Keep ADRs short — Context / Decision / Consequences is the standard skeleton. Cite incidents, PRs, or commits where useful.
